# S001 always-on-should-auto-attach

Default severity: **warning**

## What it flags

An always-on file or section (root CLAUDE.md / AGENTS.md sections, Cursor `alwaysApply: true`, Claude `.claude/rules` without `paths`, Windsurf `trigger: always_on`, Copilot repo instructions, .cursorrules, .windsurfrules, .clinerules, .roo rules) whose path references all point at one folder or one file type (at least two references).

## Why it matters

Always-on text is loaded every session even when the agent works elsewhere. Scoped rules load only when relevant and are followed more reliably.

## Bad

## Migrations
- New files go in `migrations/` and are named `migrations/NNN_name.sql`.
- Never edit an applied file in `migrations/`.

## Good

Move the section to `.claude/rules/migrations.md` with:

```yaml
---
paths: ["migrations/**"]
---
```

## How to fix

The finding suggests the exact frontmatter for the file's tool: `globs:` (Cursor), `paths:` (Claude Code), `applyTo:` (Copilot) or `trigger: glob` + `globs:` (Windsurf), or a nested AGENTS.md. `--fix` (automatic split) is planned for a later release.

## Turn it off

In `.kogentic-rules-lint.yaml`:

```yaml
rules:
  S001: off
```

Or inline, for one line: `<!-- rules-lint-disable-next-line S001 -->`.
